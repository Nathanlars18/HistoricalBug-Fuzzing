Inconsistency error with torch.sinh and torch.relu in PyTorch Model

Description:

🐛 Describe the bug


I encountered an AssertionError in a PyTorch model due to a mismatch in NaN locations when using torch.sinh followed by torch.relu.


The eager execution result and torch.compile result are different.


Minimal Reproduction:


```python
import torch
import torch.nn as nn
import numpy as np


class Model(nn.Module):

    def __init__(self):
        super().__init__()


    def forward(self, out):

        out = torch.sinh(input=out)

        out = torch.relu(input=out)

        return out



x = torch.tensor(
    [-572373.5,
     755109.125,
     330995.562],
    dtype=torch.float32
)


model = Model().to(torch.device('cpu'))


eager = model(x)


opt = torch.compile(
    model.forward,
    mode='max-autotune'
)(x)


np.testing.assert_allclose(
    eager.to('cpu').numpy(),
    opt.to('cpu').numpy(),
    rtol=1e-3,
    atol=1e-3,
    equal_nan=True,
    verbose=True
)
Error:
AssertionError:
Not equal to tolerance rtol=0.001, atol=0.001
x and y nan location mismatch:
x:
array([0., inf, inf], dtype=float32)
y:
array([nan, inf, inf], dtype=float32)
Explanation:
The input values are extremely large.
After applying sinh:
tensor([-inf, inf, inf])
The compiled ReLU kernel generated by Inductor produces incorrect numerical behavior.
The generated code contains:
auto tmp1 = std::sinh(tmp0);

auto tmp2 = tmp1 * (tmp1 > 0);

out_ptr0[x0] = tmp2;
For the value:
-inf * 0
According to IEEE_754 floating point rules:
-inf multiplied by zero results in NaN.
The eager implementation of ReLU returns:
0
The optimized implementation returns:
NaN
Expected Behavior:
torch.compile with Inductor should produce the same numerical result as eager execution.

Discussion:
xmfan:
Issue is specific to CPU Inductor's handling of torch.relu(-torch.inf).
The problem can be reproduced with:
import torch


def fn(x):
    return torch.relu(x)


x = torch.tensor(
    -torch.inf,
    device="cpu"
)


eager = fn(x)

opt_inductor = torch.compile(
    fn,
    backend='inductor'
)(x)


print(eager)

print(opt_inductor)
Output:
eager:
tensor(0.)
inductor:
tensor(nan)
Root Cause:
The CPU Inductor generated incorrect ReLU code.
The generated implementation:
tmp1 * (tmp1 > 0)
does not correctly handle negative infinity input.
Fix:
Commit:
fix cpp backend relu codegen with inf input (#117622)
The issue was fixed by changing the generated ReLU implementation.
Final Resolution:
Fixed in PR #117622.
Closed on 2024-01-21.
