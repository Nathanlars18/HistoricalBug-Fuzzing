Title:
Inconsistent float16 overflow behavior between CPU and CUDA devices


API:
torch.add


Category:
Backend Consistency


Labels:
module: cuda
module: half
module: edge cases
actionable


Environment:

PyTorch:
2.6.0+cu124


Description:

torch.add behaves inconsistently between CPU and CUDA when using float16 tensors with extremely large alpha values.


CPU implementation raises overflow error.

CUDA silently completes the operation.


Reproduction:

import torch


tensor1 = torch.randn(
    (8,1,1,1),
    dtype=torch.float16
)

tensor2 = torch.randn(
    (8,1,1,1),
    dtype=torch.float16
)


alpha = 1.04119e32


torch.add(
    tensor1,
    tensor2,
    alpha=alpha
)


Observed:

CPU:

RuntimeError:
value cannot be converted to type at::Half without overflow


CUDA:

Operation succeeds silently.


Trigger Condition:

- API: torch.add
- dtype: float16
- extremely large alpha scalar
- device difference CPU vs CUDA


Bug Pattern Candidate:

Backend-dependent dtype overflow handling inconsistency.


Potential Harness Strategy:

Run identical torch.add inputs on CPU and CUDA.

Compare:
- exception behavior
- output validity


Oracle:

CPU/CUDA behavior mismatch.
