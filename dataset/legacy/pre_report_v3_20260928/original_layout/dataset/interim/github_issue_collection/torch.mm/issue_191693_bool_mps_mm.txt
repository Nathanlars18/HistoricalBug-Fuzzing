--------------------------------------------------
Bug Summary
--------------------------------------------------

torch.mm on MPS raises an internal RuntimeError when
both input tensors are boolean dtype.

CPU rejects this operation clearly, but MPS dispatches
the operation into an unsupported matmul_bool kernel path.


--------------------------------------------------
Affected Environment
--------------------------------------------------

PyTorch Version:
2.12.0

Device:
MPS (Apple Silicon)

OS:
macOS


--------------------------------------------------
Trigger Condition
--------------------------------------------------

API:
torch.mm


Input:
2D tensors


dtype:
torch.bool


device:
mps


Operation:

torch.mm(input, mat2)


--------------------------------------------------
Reproduction
--------------------------------------------------

import torch

a = torch.randint(
    0,
    2,
    (4,4),
    dtype=torch.bool,
    device="mps"
)

b = torch.randint(
    0,
    2,
    (4,4),
    dtype=torch.bool,
    device="mps"
)

torch.mm(a,b)


--------------------------------------------------
Observed Behavior
--------------------------------------------------

RuntimeError:

Failed to create function state object for:
matmul_bool


--------------------------------------------------
Expected Behavior
--------------------------------------------------

The operation should reject unsupported dtype
with a clear error message, similar to CPU behavior.

Root Cause Hint

Backend dispatch lacks proper dtype validation
before entering MPS matmul implementation.
