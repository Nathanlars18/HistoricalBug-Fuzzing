Description:

torch.compile with the Inductor backend fails when torch.addmm is called with
beta=0 and the input bias tensor has a shape that is not broadcastable to the
matrix multiplication output.

Eager execution succeeds because beta=0 causes the bias contribution to be ignored,
while the compiled version performs shape validation during compilation and fails.


Minimal Reproduction:

```python
import torch


def f(bias, x, weight):

    return torch.addmm(
        bias,
        x,
        weight.t(),
        beta=0.0,
        alpha=0.25
    )


x = torch.randn(
    3,
    7,
    device="cuda"
)


weight = torch.randn(
    11,
    7,
    device="cuda"
)


bias = torch.zeros(
    7,
    device="cuda"
)


compiled_out = torch.compile(
    f,
    backend="inductor",
    fullgraph=True
)(
    bias,
    x,
    weight
)
Observed Behavior:
Eager execution:
Returns:
shape (3,11)
torch.compile execution:
Fails with:
BackendCompilerFailed
The compiler reports broadcasting failure because the bias shape does not match
the output matrix shape.
Expected Behavior:
torch.compile should preserve eager semantics.
Since beta=0 means the bias contribution is unused,
the operation should successfully compile.
