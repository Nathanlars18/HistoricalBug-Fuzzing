Issue ID:
#60997

Title:
Dispatcher doesn't handle ops with an empty list of tensors (e.g. torch.cat())

URL:
https://github.com/pytorch/pytorch/issues/60997


Description:

While working on another issue (#60993), the PyTorch developers found that torch.cat() does not handle an empty list of tensors gracefully.

The problem is related to the dispatcher mechanism rather than torch.cat implementation itself.

When torch.cat() receives an empty Tensor list, the dispatcher cannot determine which backend kernel should be selected because there are no Tensor arguments available to provide dispatch information such as device type or dispatch key.


Affected API:

torch.cat()


Trigger Condition:

Calling torch.cat() with an empty Tensor list.

Example:

import torch

torch.cat(())


Observed Behavior:

The operation fails with a NotImplementedError.

Example error:

NotImplementedError:
There were no tensor arguments to this function
(e.g., you passed an empty list of Tensors),
but no fallback function is registered for schema aten::_cat.


Expected Behavior:

The API should handle the invalid empty Tensor list input gracefully.

The developers discussed that torch.cat() with an empty list is not a well-defined mathematical operation because:

1. The result tensor shape cannot be determined.
2. The dtype cannot be inferred.
3. The device cannot be inferred.

Therefore, raising a clear error is preferable.


Root Cause:

PyTorch dispatcher requires Tensor arguments to determine the correct dispatch kernel.

For torch.cat():

Input:
Tensor[]

Normally:

Tensor arguments provide:
- device information
- dtype information
- dispatch key


However:

torch.cat([])

contains no Tensor objects.

Therefore, the dispatcher cannot select an appropriate backend implementation.


Bug Pattern Category:

Input Container Boundary

Sub-category:

Empty TensorList


Affected Components:

- PyTorch Dispatcher
- aten::_cat
- TensorList argument handling


Fuzzing Relevance:

This bug demonstrates that Tensor container arguments are important fuzzing targets.

Traditional tensor mutation strategies usually modify:

- tensor shape
- dtype
- device
- memory layout

but may miss container-level edge cases.

Important generated cases:

1. Empty Tensor list

Example:

torch.cat([])


2. Single Tensor list

Example:

torch.cat([x])


3. Multiple Tensor list with boundary tensors

Example:

torch.cat([empty_tensor, normal_tensor])


Recommended Harness Generation Guidance:

When generating torch.cat() test cases, include:

- random Tensor list length
- zero-length Tensor lists
- single-element Tensor lists
- combinations of empty and non-empty tensors

Importance:

Medium-High

Reason:

Although this issue is relatively simple, it exposes an important class of API boundary failures caused by invalid container inputs.

It provides useful guidance for LLM-based harness generation by showing that fuzzers should mutate not only tensor properties but also the structure of Tensor arguments.
