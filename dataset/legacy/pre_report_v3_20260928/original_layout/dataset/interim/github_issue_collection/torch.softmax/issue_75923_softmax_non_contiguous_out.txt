aten::_softmax.out doesn't work with non-contiguous Tensors

Description:

The internal aten::_softmax.out implementation produces incorrect results
when the output tensor provided through the out parameter is non-contiguous.

The generated output is partially written into incorrect memory locations,
causing some elements to remain unchanged.

The resulting tensor contains invalid softmax values,
including negative values that should never appear in softmax output.


Trigger Condition:

Operation:

aten::_softmax.out


Required conditions:

1. Use the out parameter.

2. The output tensor is non-contiguous.

3. Perform softmax computation.


Trigger example:

```python
inp = torch.rand(2,3)

out = create_non_contiguous_tensor()

torch._softmax(
    inp,
    0,
    half_to_float=False,
    out=out
)
Minimal Reproduction:
import torch
from torch.testing import make_tensor


inp = torch.rand(2,3)


out = make_tensor(
    inp.shape,
    dtype=inp.dtype,
    device=inp.device,
    noncontiguous=True
)


torch._softmax(
    inp,
    0,
    half_to_float=False,
    out=out
)


expected = torch._softmax(
    inp,
    0,
    half_to_float=False
)


print("Actual:")
print(out)

print("Expected:")
print(expected)
Observed Behavior:
The output tensor is incorrect.
Example:
Actual:
tensor([
    [0.5257, 0.4881, 0.3627],
    [-2.9375, 8.6783, 7.0183]
])
Expected:
tensor([
    [0.5257, 0.6373, 0.4881],
    [0.4743, 0.3627, 0.5119]
])
Some output positions are not updated correctly.
Expected Behavior:
Softmax should produce identical correct results regardless of
whether the output tensor storage is contiguous or non-contiguous.
