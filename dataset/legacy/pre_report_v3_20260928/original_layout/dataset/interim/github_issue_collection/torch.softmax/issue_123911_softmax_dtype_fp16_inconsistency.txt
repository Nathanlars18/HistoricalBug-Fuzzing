Description:

The behavior of:

torch.softmax(inp, dtype=torch.float32).to(torch.float16)

is not numerically equivalent to:

torch.softmax(inp)

when the input tensor uses float16 precision.

The reporter investigated inconsistent outputs between SDPA and eager implementations.
The difference was traced to different softmax computation paths.

Although the numerical difference is small for a single operation, the error can accumulate through multiple neural network layers and result in larger output deviations.


Trigger Condition:

Input tensor:
- dtype: float16
- device: CUDA GPU

Operation:
- Apply torch.softmax directly on fp16 tensor
- Compare with torch.softmax using dtype=float32 followed by cast back to fp16


Minimal Reproduction:

```python
import torch

softmax_inp = torch.randn(
    1,
    32,
    1238,
    1238,
    device="cuda",
    dtype=torch.float16
)

res_softmax_0 = torch.softmax(
    softmax_inp,
    dim=-1
)

res_softmax_1 = torch.softmax(
    softmax_inp,
    dim=-1,
    dtype=torch.float32
).to(torch.float16)

absdiff = (res_softmax_0 - res_softmax_1).abs()

print(absdiff.max())
Observed Behavior:
The two computation paths produce different results.
Example:
max absdiff softmax:
tensor(0.000488, device='cuda:0', dtype=torch.float16)
The difference can accumulate in deep transformer models and produce larger final output errors.
Expected Behavior:
torch.softmax(inp, dtype=torch.float32).to(torch.float16)
and
torch.softmax(inp)
should provide numerically equivalent results for float16 inputs.
